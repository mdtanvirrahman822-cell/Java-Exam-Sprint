###### **What is a UML Class Diagram** 

- UML stands for 

- It can be used to model an **object-oriented system** 

- A UML class diagram depicts the structure of a system by showing its classes, their attributes and methods, and the relationships between them 

- In plain terms, it is a blueprint of the classes in a program, without 

any of the actual code 

3 

###### **Why Draw It First** 

- It's easier to spot a bad design on a whiteboard than after writing 

   - 200 lines of code 

- It's a shared visual language that is understood by non-technical 

people

###### **Class Box Syntax** 

**Class Name visibility  name : Type** 

**visibility  name(paramName : ParamType) : ReturnType** 

- Top: the class name. Middle: attributes. Bottom: methods 

- Attributes: visibility symbol, then name, a colon, then the type 

- Methods: visibility symbol, name, parameters in brackets (name: 

type), a colon, then the return type

###### **<mark>Three other Relationships</mark>** 

- Three relationships describe how one class can relate to another: 

**association** , **aggregation** , and **composition** 

- They look similar but mean very different things 

- The key question for telling them apart: does one side own the 

other, and does one depend on the other to exist? 

14

**class Doctor { private Patient currentPatient;** 

**void diagnose(Patient patient) { System.out.println("Diagnosing " + patient.getName()); } void setCurrentPatient(Patient patient) { this.currentPatient = patient; } }**

- Neither class is a container for the other, they're just related 

- Both classes, and their objects, can exist completely independently

###### **<mark>Aggregation</mark>** 

**class Team { private List<Player> players;** 

**void addPlayer(Player player) { players.add(player); } }** 

**class Player { private String name; }** 

- Team is a **container** for Players, this is a real **has-a** relationship 

- Players are added from outside, not created inside Team 

- Deleting a Team doesn't delete its Players, they can join another Team

###### **<mark>Composition</mark>** 

**class Car { private Engine engine; Car() { engine = new Engine(); } } class Engine { void start() { System.out.println("Engine started"); } }** 

- Car creates its own Engine **internally** 

- No other code holds a separate reference to that Engine 

- The Engine's lifetime is entirely tied to this one Car

###### **What is Multiplicity** 

- Multiplicity states how many instances of one class can relate to 

how many instances of another 

- Written as a number or range placed near each end of the 

   - relationship line 

- It applies to association, aggregation, and composition lines alike 

22

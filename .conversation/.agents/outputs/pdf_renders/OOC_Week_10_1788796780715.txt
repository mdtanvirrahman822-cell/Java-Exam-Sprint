Upcasting

Upcasting
●
Implicit upcasting takes place
●
There is no need to explicitly cast up 
the inheritance tree
●
Compiler knows that cat is an 
Animal, no error
public class Animal {
    String type = “Animal”;
    public void eat() {
        // ... 
    }
}
public class Cat extends Animal {
    String type = “Cat”;
    public void meow() {
         // ... 
    }
}
Cat c = new Cat();
Animal a = c;
// Equivalent:
// Animal a = new Cat();

--- PAGE 9 ---
Overridden Methods in Upcasting
public class Animal {
    void display() {
        System.out.println("Animal");
    }
}
public class Dog extends Animal {
    @Override
    void display() {
        System.out.println("Dog");
    }
}
Animal a = new Dog();
a.display();
// ‘Dog’ is printed
●
Overridden methods are 
accessible
●
The object type (Dog) 
determines which method runs
●
This is runtime polymorphism

--- PAGE 11 ---
Downcasting
●
Casting from a superclass to a subclass is downcasting
●
Requires explicit casting
●
Used to access subclass-speciﬁc members
●
May throw ClassCastException if the object is not actually an 
instance of the subclass

--- PAGE 12 ---
Animal a = new Cat();   // Upcasting
Cat c = (Cat) a;   // Downcasting
c.meow();
Safe Downcasting
●
Why doesn't Java do this implicitly?
●
Because Java cannot guarantee that the object is actually a 
Cat
●
This is safe downcasting
●
Because the object really is a Cat

--- PAGE 13 ---
Animal a = new Cat();
Dog d = (Dog) a;
Unsafe Downcasting
●
Will this compile?
○
Yes
●
Will this run?
○
No
●
Java throws ClassCastException
●
At compile-time, Java assumes a is a Dog but at runtime, it sees 
the actual object is a Cat

--- PAGE 14 ---
Unsafe Downcasting
Dog dog = new Animal(); // Compilation Error
●
Trying to assign an Animal object directly to a Dog reference
●
The compiler knows that a general Animal is not guaranteed to 
be a Dog, so it rejects the assignment immediately
Animal animal = new Animal();
Dog dog = (Dog) animal;
●
This compiles but at runtime, Java checks the object and ﬁnds 
that it's actually an Animal, not a Dog
●
Throws a ClassCastException

--- PAGE 16 ---
Safe Downcasting with instanceof
●
bark() is called only when 
animal is actually a Dog
●
meow() is called when it is a 
Cat
●
No chance of 
ClassCastException
if (animal instanceof Dog){
    Dog d = (Dog) animal;
    d.bark();
} else if (animal instanceof Cat) {
    Cat c = (Cat) animal;
    c.meow();
}

●

--- PAGE 18 ---
instanceof Pattern Matching
●
Java 14+ allows this: 
if (animal instanceof Dog d) {
    // The variable 'd' is automatically cast and ready to use
    d.bark();
}
●
d is called a pattern variable here and its scope is within this 
block only

--- PAGE 19 ---
Rules of Pattern Matching
1. Conditional AND (&&)
You can use the pattern variable immediately on the right side of an 
&& operator because the right side only runs if the type check passes
if (animal instanceof Dog d && d.getAge() > 5) {
    d.bark();
}

--- PAGE 20 ---
Rules of Pattern Matching
2. Conditional OR (||)
You cannot use the pattern variable on the right side of an || operator. 
If the left side fails, the variable is not initialized.
if (animal instanceof Dog d || d.getAge() > 5) {
    d.bark();
}
// Compilation Error

--- PAGE 21 ---
Rules of Pattern Matching
3. Negated Condition (!)
If you invert the condition using a negative check, the scope of the 
variable shifts into the else block
public void examineAnimal (Animal animal) {
    if (!(animal instanceof Dog d)) {
        return; // d is not in scope here
    }
    // d is in scope here
    d.bark();
}
